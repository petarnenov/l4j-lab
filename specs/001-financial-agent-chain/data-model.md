# Phase 1 Data Model: Financial Agent Chain

**Date**: 2026-09-12 | **Plan**: [plan.md](./plan.md) | **Spec**: [spec.md](./spec.md)

Two persisted tables, one committed dataset file, and four in-memory domain types that form
the node boundaries. Both tables are `@MappedEntity` Java records read through
`@JdbcRepository` interfaces, per R-011. Flyway owns the schema; nothing is generated at
startup. Boundary field lists live in
[contracts/node-boundaries.md](./contracts/node-boundaries.md) and are not repeated here.

## Persisted entities

### chain_run

One execution of the four-node chain. Maps to the Chain Run entity in the specification.

| Column | Type | Notes |
|--------|------|-------|
| id | uuid, primary key | Generated by the application, returned to the client |
| company_id | text, not null | The learner's selection |
| period | text, not null | Reporting period, `YYYY-Qn` |
| status | text, not null | See the state machine below |
| current_node | text, null | Name of the node executing now, null once terminal |
| failed_node | text, null | Name of the node that failed or timed out, null unless status is FAILED or TIMED_OUT |
| failure_reason | text, null | Learner-facing message, never a stack trace |
| provider_mode | text, not null | `LOCAL` or `CLOUD`, resolved at run start |
| model_id | text, not null | The configured model identifier |
| summary_text | text, null | Populated when the fourth node succeeds |
| started_at | timestamptz, not null | |
| ended_at | timestamptz, null | Null while running |

Indexed on `started_at` descending, which is the only ordering the history list uses.

**Validation rules**

- `company_id` and `period` must both match a record in the dataset before the row is written.
- `failed_node` and `failure_reason` are both present or both absent, enforced by a check
  constraint. Both are present for `FAILED` and for `TIMED_OUT`, so the learner can name the
  node in either case (SC-006).
- `ended_at` is null exactly when `status` is `PENDING` or `RUNNING`.

**State transitions**

```text
PENDING ──> RUNNING ──> SUCCEEDED
                 │
                 ├────> FAILED     (a node raised a handled failure)
                 └────> TIMED_OUT  (the model call exceeded its timeout)
```

`PENDING` exists so the write endpoint can return before the executor picks the run up. No
transition moves backwards, and no terminal state changes again. Satisfies FR-015 and FR-019.

### node_execution

One node's participation in one run. Maps to the Node Execution entity.

| Column | Type | Notes |
|--------|------|-------|
| id | uuid, primary key | |
| run_id | uuid, not null | References `chain_run(id)`, cascade delete |
| position | smallint, not null | 1 through 4 |
| node_name | text, not null | `PrepareRequest`, `RetrieveRecords`, `ComputeIndicators`, `Summarize` |
| input_payload | jsonb, not null | The boundary structure the node received, mapped through Micronaut Data's JSON data type |
| output_payload | jsonb, null | Null when the node failed, same mapping |
| succeeded | boolean, not null | |
| failure_reason | text, null | Present only when `succeeded` is false |
| started_at | timestamptz, not null | |
| duration_ms | integer, not null | |
| model_request_text | text, null | Summarize node only |
| model_response_text | text, null | Summarize node only |
| input_tokens | integer, null | Summarize node only, when the provider reports it |
| output_tokens | integer, null | Summarize node only, when the provider reports it |

Unique on `(run_id, position)`. Indexed on `run_id`.

**Validation rules**

- `position` and `node_name` must agree with the fixed chain order, enforced in code by the
  runner and by a check constraint on the allowed name set.
- The four model columns are null for positions 1 through 3.
- `output_payload` is null exactly when `succeeded` is false.
- No column may contain the provider credential. The writer never receives it.

Together these satisfy FR-009, FR-010, FR-011, and Principle V.

## Committed dataset

### FinancialRecord, in `backend/src/main/resources/data/companies.json`

One company's reported figures for one period. Read-only, loaded at startup, never written.

| Field | Type | Notes |
|-------|------|-------|
| companyId | string | Stable key, for example `northwind-lighting` |
| companyName | string | Fictional display name |
| period | string | `YYYY-Qn` |
| revenue | decimal | |
| costOfGoodsSold | decimal | |
| netIncome | decimal | May be negative |
| currentAssets | decimal | |
| currentLiabilities | decimal | |
| totalDebt | decimal | |
| equity | decimal | Zero in at least one record, to exercise the not-applicable path |

**Validation rules**

- `(companyId, period)` is unique across the file, checked at startup with a failure that
  names the duplicate.
- Every company has a contiguous run of periods, so that prior-period lookup has a defined
  answer for every period except the first.
- All amounts are in one currency unit and no currency conversion exists in this feature.

## Computed types

### IndicatorSet

The third node's output for one run. Five indicators, each either a value or a reason it does
not apply.

| Indicator | Formula | Not applicable when |
|-----------|---------|---------------------|
| revenueGrowth | (revenue − priorRevenue) ÷ priorRevenue | No prior period, or prior revenue is zero |
| grossMargin | (revenue − costOfGoodsSold) ÷ revenue | Revenue is zero |
| netMargin | netIncome ÷ revenue | Revenue is zero |
| currentRatio | currentAssets ÷ currentLiabilities | Current liabilities is zero |
| debtToEquity | totalDebt ÷ equity | Equity is zero |

Each entry carries the indicator name, either a value or a not-applicable reason, and the
record fields it was derived from, which is what lets the interface show the summary's
provenance. Values use scale 4 and `RoundingMode.HALF_UP`, per R-005, so SC-005 holds.

### RunSummary

The fourth node's output. Holds the summary text, the model identifier, the provider mode, and
the token counts when reported. Persisted onto both `chain_run.summary_text` and the
summarizing node's `node_execution` row, the first for listing and the second for the trace.

## Relationships

```text
FinancialRecord (file, read-only)
        │  looked up by (companyId, period) and by (companyId, prior period)
        ▼
   ChainRun 1 ─── 4 NodeExecution
        │
        └── summary_text, denormalised from the fourth NodeExecution
```

The denormalisation is deliberate. The history list needs a summary without loading four JSONB
payloads per row, and the value is written once at the end of a run and never updated.

## Out of scope

No embedding, no vector column, and no use of the pgvector extension in this feature. The
extension stays installed because the project stack declares it, but nothing here writes to it.
